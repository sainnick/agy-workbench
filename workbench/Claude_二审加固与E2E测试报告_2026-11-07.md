### P1-3 附件与回执顺序（`weixin-send.mjs`）

- 有附件时的顺序：
  1. 先发纯正文，不带 🧾；
  2. 逐个上传附件；
  3. 全部送达后，才补发「🧾 验收回执」，并写入 `delivery: sent` 的账、核销承诺、排审查。
- 任一附件失败：
  - 立刻发「⚠️ 附件上传失败，本次交付未完成（x/y 已送达；失败：…）…回执作废」；
  - proofs.jsonl 记 `verdict/delivery = attachment_failed`、`sent:false`；
  - 不核销、不登记，退出码 4。
- 新增参数 `--task=<msg编号>` 和 `--commitment=<c编号>`，核销时会传入明确的 taskId 和最后一条 messageId。

### P1-4 承诺账本（`commitments.mjs`）

- 开头是「进度汇报 / 进度更新 / 阶段汇报…」（允许前面带【项目名】）且没给新的具体时间点 → 不新建承诺。
- 一条消息最多合成 1 条承诺。**同一窗口最多 1 条活跃承诺**：
  - 后续承诺和进度合并进这条（更新文本、保留 originalText、mergedCount+1）；
  - 只有给出新时间点时才顺延截止时间；
  - 历史上同一窗口堆积的多条会收拢成 1 条，其余记为 `merged`。
- 核销规则收紧：
  - 有 `--task` 时，只核销该任务的承诺；
  - 没有 taskId 时，只核销属于当前派发任务、或交付物文件名/关键词明确对得上（匹配分 ≥ 4）的那条；
  - 都对不上就保持待核验；unassigned 会话、别的窗口一律不核销。

## 如实说明：仍未解决的边界

1. **HMAC 不是操作系统级隔离**：AGY 和 job-runner 是同一个 macOS 用户，AGY 理论上能读到 `~/.claude-cli/.ticket_secret` 并自己签票。这次堵住的是「手写一份 JSON 就能冒充」。要真正隔离，需要让 job-runner 以独立用户运行，或把密钥放进钥匙串并加访问控制。
2. **工作台令牌防的是跨站请求和盲打 POST**：能先 GET / 的本机进程仍能读到令牌，这是「同源注入」方案本身的上限。
3. **Claude 调用证据按「项目目录 + 6 小时」判断**：同一目录 6 小时内有过任何一次真实 Claude CLI 会话就算有证据，没法细到「这一句话说的那次审查」。实测 H3 目录今天确有 Claude CLI 会话，所以 H3 写「让 Claude 审了」不会被标；Echo 目录没有，会被就地打标。
4. **附件失败用的是假通道注入**，没有对真实微信 CDN 做断网故障注入。告警消息本身如果也发不出去，只会写本机日志。
5. GPT 提到的另外两项本次没动：死信队列（重试耗尽仍会标记为已处理），以及 GitHub Actions CI。
